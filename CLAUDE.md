## Commands

- `npm run dev` — dev server on http://localhost:3000
- `npm run build` — production build (also the type-check that matters)
- `npx next typegen && npx tsc --noEmit` — quicker type-check. The global `PageProps<"/route">` / `LayoutProps` types only exist after typegen (or dev/build) has run, so run it after adding a route.
- `npm run lint` — ESLint (`eslint-config-next`, react-hooks 7: `setState` inside `useEffect` is an error, hence the `useSyncExternalStore` store).
- There is no test suite. Verification is visual: run the dev server and check pages in a browser at 1280px and 390px.

Stack: Next.js 16 App Router, React 19, TypeScript, Tailwind CSS v4, `lucide-react`. Read `node_modules/next/dist/docs/` before using a Next API from memory; this Next version differs from older training data (`params`/`searchParams` are Promises and repeated query keys arrive as arrays; `priority` on `<Image>` is deprecated in favour of `preload`; `error.tsx` receives `{ error, retry }`; `next/form` scrolls to the top unless `scroll={false}`; `data-scroll-behavior="smooth"` is required on `<html>` for smooth anchor scrolling).

## What this is

ZARKOONY, a luxury Pakistani womenswear store where everything is custom stitched and made to order. The whole storefront exists as a frontend with mock data: home, shop + occasion categories, named collections, product pages with the measurement flow, search, cart, mock checkout + confirmation, wishlist, a mock account (login/register/orders/profile/addresses), made-to-order guides, a custom-orders quote page (`/custom-orders`), about, contact, FAQ, shipping, returns and four policies. There is no backend: see "Mock state" below.

Design sources, in order of authority:
1. The Google Stitch project "ZARKOONY Luxury Fashion Store" — homepage layout, sections, copy, images. Its `DESIGN.md` ("Haute Couture Atelier") holds the colour tokens, component rules and the made-to-order drawer spec.
2. baroque.pk — the owner wants its typography and interactions matched exactly, and its site *structure* (navigation, listing, product, cart, account, customer-care pages) was the benchmark for the inner pages. Measured values: Cabin for uppercase labels/headings, Figtree for body and buttons, no serif anywhere (Playfair was removed), only the 400 and 700 cuts, body text `#1c1c1c` at 14px on phones and 15px from 700px, inputs 48px tall, one tracking value (0.18em) everywhere, Baroque's heading scale as `@theme` text tokens (`text-title` 22–30.8px page and section titles, `text-display` 24.2–35.2px, `text-product` 15.4px product titles in `#818589`, `text-label` 13.2px/1.7 for card names, accordion and facet labels and footer headings; prices stay 13px bold), section headings 22–30px fluid, buttons 46px tall with the wipe-out hover, transparent header over the hero, 8-second image creep on category and collection cards, second-image cross-fade on product cards, thumbnail rail that slides a one-image-at-a-time horizontal gallery. The product page follows Baroque's scale: a centred 1264px container, a 56px thumbnail rail 80px from 2:3 images about 631px wide, a 413px info column, a 15.4px uppercase title, 44px size boxes in a row and a full-width add-to-cart button. The info column carries only what Baroque's does: title, price, SKU line, size row with the size chart, quantity, add to cart and four short accordions (details, delivery, description, exchanges); no breadcrumbs, badges or explanatory copy.

Zero border radius everywhere (the only round things are the 8px header dots and the floating WhatsApp button, round and WhatsApp green at the owner's request). Never use `rounded-*` elsewhere. No Baroque names, images, copy or code.

## Architecture

**Data lives in `lib/`, markup in `components/`, routes in `app/` compose them.**
- `lib/products.ts` — `Product` (16 mock products; photos are the 12 Stitch assets reused, swap by editing `images`), `categories` (occasions: formals, bridal, festive, luxury-pret), `collections` (signature, luxury-edit, velvet-winter, eid-edit), `measurementFields` (8, inches, with hints and sanity bounds), `standardSizes`, `sizeChart`, `MeasureItem`, `formatPrice` (fixed `en-US` locale so server and client agree), `stitchingLabel`.
- `lib/catalog.ts` — pure helpers: `parseListingParams` (URL → filters/sort/page, arrays for repeated keys), `runListing` (filter + sort + paginate, 12 per page), `listingQuery` (state → query string, defaults omitted), `facetValues`, `searchProducts`, `relatedProducts`, `productBySlug`, `productsInCategory` (`"new-arrivals"` = `isNew`), `productsInCollection`.
- `lib/orders.ts` — `CartLine`, `Order`, `orderStages` (the five-stage production timeline), `createOrder`, `sampleOrders` (two seeded orders every mock account shows), `countries` + `countryName`, `deliveryFee` (international charge for the US), `provinces`, `paymentMethods` with `paymentMethodsFor(country)`, `TransferDetails`, `formatDate`.
- `lib/content.ts` — `facts` (every business number: stitching windows, express fee, delivery, alteration and cancellation rules; all placeholders marked `TODO confirm`), `careByFabric`, and the structured copy (`ContentPage` of sections of blocks) for about, made-to-order, measurement guide, size guide, FAQ, shipping, returns and `policies`.
- `lib/site.ts` — brand strings, contact details (placeholders), the two-level `nav` tree for the drawer (derived from categories/collections), `popularSearches`, `footerColumns`, social SVG paths (hrefs still `#`), `site.url` from `NEXT_PUBLIC_SITE_URL`.
- `lib/home.ts` — hero, category sections, banners and strip copy. A `Cta` is either `{ href }` or `{ item: MeasureItem }`; `components/Cta.tsx` renders the first as a link and the second as a drawer trigger.

**Routes.** `/shop`, `/shop/[category]`, `/collections/[slug]` and `/search` render `components/shop/Listing.tsx` with `searchParams` (so they are dynamic); `/product/[slug]` and `/policies/[slug]` are static with `generateStaticParams` + `dynamicParams = false`. Content pages render `components/ContentPage.tsx` from `lib/content.ts`. `/checkout/confirmation` reads `?order=` on the server and passes the id to a client component (no `useSearchParams`). `/account` uses route groups: `(auth)` for login/register/forgot-password and `(dashboard)` whose layout wraps pages in `AccountShell` (skeleton until hydrated, sign-in prompt without a session). `app/sitemap.ts` and `app/robots.ts` list routes; `not-found.tsx` and `error.tsx` exist.

**Mock state — `components/Store.tsx`.** Cart, wishlist, session and placed orders each live in a `localStorage` key (`zarkoony:*`) behind `useSyncExternalStore` with an empty server snapshot, so SSR and hydration agree. Hooks: `useCart/useWishlist/useSession/useOrders/useHydrated`; actions are plain functions (`cartActions`, `wishlistActions`, `sessionActions`, `orderActions`), no provider. Standard-size lines merge by slug + size; custom-measured lines are always separate. Any view that depends on stored state renders a skeleton until `useHydrated()` is true.

**Server by default; the client files are:** `Overlays.tsx` (context + the four native `<dialog>`s: drawer menu with `<details>` accordions, search bar with live suggestions via `searchProducts` and a `next/form` submit to `/search`, cart drawer with steppers, measurement drawer; exports `Trigger`, `useOverlays` (its `addToCart` adds a line and opens the cart), `CartDot`, `WishlistDot`, `Stepper`), `MeasureForm.tsx` (Baroque's size row and quantity, then add to cart; Custom adds one measurements step; only the current step is rendered and validated with `checkValidity`, shared by the drawer and the product page), `Store.tsx`, `HeaderFrame.tsx` (`data-solid` on scroll), `HeroMedia.tsx` (hero reveal, listens for `load` via a ref because `next/image`'s `onLoad` waits on `img.decode()` which never resolves for cached images), `Reveal.tsx` (IntersectionObserver scroll fade-up, hidden state only under `@media (scripting: enabled)` and no reduced motion), `WishlistButton.tsx`, `shop/FilterForm.tsx` (GET `next/form` with `scroll={false}` + `replace`, auto-submits on change, keyed on the URL state so chip links reset it), `product/ProductForm.tsx` (MeasureForm + size-guide dialog + wishlist), `cart/CartView.tsx`, `checkout/Checkout.tsx`, `orders/OrderConfirmation.tsx`, `WishlistView.tsx`, `account/*`, `ContactForm.tsx`, `CustomOrderForm.tsx` (quote request: 2–3 pictures with object-URL previews kept in sync with the file input via `DataTransfer`, size, contact, time frame; native validation, nothing sent), `NewsletterForm.tsx`. Server components open overlays through `<Trigger opens="menu|search|cart|measure" item={…}>`.

**Region and currency.** The visitor is "PK" or "US": `proxy.ts` sets the `zarkoony-region` cookie from Vercel's `x-vercel-ip-country` on the first request, an inline script in `app/layout.tsx` sets `<html data-region>` before first paint (cookie, else `Asia/Karachi` time zone → PK, else US), and the header chooser (`RegionChooser`, `regionActions`/`useRegion` in `Store.tsx`) overrides both. Prices are PKR in the data; `components/Price.tsx` renders `<Price value>` as both `PKR 18,500` and `$67` (`formatUsd`, `USD_RATE` placeholder) and `Regional` does the same for any copy, with `app/globals.css` showing the matching span, so server components stay static and nothing flashes. Checkout defaults its country to the region and sets the region when the country changes.

**Forms.** `components/Field.tsx`: `Field` (label + input + inline error) and `invalidFields(form)` (native constraint validation → messages keyed by name, focuses the first). Forms are `noValidate` and call it on submit.

**Header states are CSS, not React.** `.site-header` in `app/globals.css`: white by default; transparent with white text and a CSS-inverted logo when `body:has([data-transparent-header])` (set on the Hero) and the header is neither hovered nor `[data-solid]`. The header's negative `margin-bottom: calc(-1 * var(--header-height))` pulls the hero underneath it; `--header-height` must match the header's real height per breakpoint. The country chooser is a native `popover` (`#country-menu`, opened by `popoverTarget` buttons in the header, drawer and footer).

**Global styling conventions in `app/globals.css`:**
- `@theme` holds the Stitch colour tokens, `--tracking-label`, the motion tokens (`--duration-fast/medium/slow` = 200/400/800ms, `--ease-standard`, `--ease-wipe`) and the announcement `marquee` keyframes. Use `duration-(--duration-fast)` etc. in classes.
- `caps` utility = Cabin + uppercase + 0.18em tracking; pair it with a text size (`text-label`, `text-product`, `text-title` for Baroque's exact sizes). `link-underline` = the retracting 1px underline. `.skeleton` = loading shimmer.
- `.btn-white` / `.btn-black` implement Baroque's two-gradient-layer hover wipe; use these classes on both `<a>` and `<button>` rather than restyling buttons (`!border-black !text-black` turns `btn-white` into an outline button on white).
- Accordions are native `<details>`; `::details-content` + `interpolate-size` animate them where supported. Dialogs and popovers use `@starting-style` / `starting:` for entrances; everything is `motion-reduce`-safe.
- Inputs are 16px on phones (`text-base sm:text-[15px]`) so iOS doesn't zoom on focus.

**Images** are the brand shoot, converted to 2000px JPEGs in `public/images/products/<outfit>/<n>.jpg` (six outfits, each shared by two or three products via `pick()` in `lib/products.ts` so every product leads with a different view), plus `hero/atelier-salon.jpg` (1672×941), `hero/classical-salon.jpg` (2400×1600) and the `collections/velvet-winter.jpg` triptych. The PNG source folder `public/images/High Quality Pics` is git-ignored. `brand/logo.png` is black-on-transparent, trimmed to its ink so it centres. Always `next/image` with `fill` + `sizes`; the hero and the first gallery image use `preload`, above-the-fold cards `loading="eager"`.

## Mock state and known leftovers

Nothing is sent anywhere. Orders, the session (any e-mail + password "signs in" on this device; passwords are never stored), cart and wishlist exist only in the browser's localStorage. Checkout takes no payment. The delivery country chooses the flow: Pakistan offers cash on delivery or bank transfer (the atelier account is shown and the customer enters their transfer details and attaches a receipt, whose name alone is stored); the United States offers card or ACH "via Stripe", which is explained on the page and, until keys and a route handler exist, lands on the confirmation like any other order (see the `ponytail:` note in `Checkout.tsx`). The contact and newsletter forms only show a success message. Business facts in `lib/content.ts` and contact details in `lib/site.ts` are placeholders modelled on Baroque's terms and marked `TODO confirm`. Social links are `#`. `site.internationalUrl` is no longer linked from the storefront (the US is served here) but still defined.
